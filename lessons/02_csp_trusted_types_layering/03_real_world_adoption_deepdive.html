Why CSP almost always ships first

A basic script-src policy can often be added to an existing application with comparatively contained blast radius: it mostly affects WHERE scripts load from and WHETHER inline scripts/eval run, which a team can audit by grepping their own codebase for inline <script> tags and eval/Function usage. Painful, but bounded and enumerable.

Why Trusted Types tends to ship later, and why that's not laziness

require-trusted-types-for affects every single call site that assigns to a guarded sink, across an entire codebase and every third-party library it depends on — and Module 19's real finding (the Function constructor's incomplete Trusted Types support) is exactly the kind of surprise that makes this riskier to enable blind. A team can't safely flip it on without first knowing how many sink call sites exist and which of their dependencies even work correctly under it.

The real migration shape this course's own modules mirror

Module 17's "default" policy pattern is not a pedagogical simplification — it's the actual real-world on-ramp: ship require-trusted-types-for alongside a permissive "default" policy first (avoiding an instant outage), observe real violations via Module 21's reporting pipeline in production, then progressively either tighten the default policy's rule or migrate specific call sites to their own named, narrowly-scoped policies (Module 16's pattern) — shrinking what the permissive default has to cover over time.

Where Module 20's allowlist fits into that timeline

The trusted-types policy-name allowlist (Module 20) is typically tightened LAST, once a team knows the final, settled set of policy names their application actually needs — adding it too early, before the migration above has stabilized which policies exist, would just mean constantly editing the allowlist as new legitimate policies get introduced during migration.

The throughline

Every module in Phase 3 of Track 2 (Modules 17, 20, 21) that might look like "extra mechanism" in isolation is really infrastructure for exactly this staged rollout — not for a green-field application that gets to enable everything strictly from day one.
