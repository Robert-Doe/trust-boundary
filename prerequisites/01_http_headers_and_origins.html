What a response header is

When a browser asks a server for a page, the server's reply has two parts: a block of headers (plain-text Name: value lines) and then the body (the actual HTML/JS/image bytes). Headers are metadata about the body — they never appear on the rendered page, and JavaScript on the page can't read most of them either. A raw response looks like this on the wire: 

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Security-Policy: default-src 'self'
Content-Length: 512

<!doctype html>
<html>...</html>

Content-Security-Policy is just one more header line. The browser parses its value before it starts executing anything in the body. That ordering is the whole reason CSP can act as a gate: policy arrives before any script from the body has had a chance to run.

The origin triple

A browser's most important trust boundary is the origin: the exact combination of scheme, host, and port. 

https://example.com:443/path?query
└──┬──┘ └────┬─────┘ └┬┘
 scheme     host      port

Origin = (scheme, host, port)  →  ("https", "example.com", 443)

Two URLs are same-origin only if all three match exactly. All of these are different origins from https://example.com:

URLWhy it differs
http://example.comscheme differs (http vs https)
https://example.com:8443port differs
https://api.example.comhost differs (subdomain counts as a different host)

The Same-Origin Policy (the default, before any CSP exists)

Before you add a single security header, the browser already enforces a baseline rule called the Same-Origin Policy (SOP): a script running on origin A cannot read data (DOM, cookies, response bodies, local storage) belonging to origin B. This is why, for example, a tab open to your bank can't have its JS read the DOM of a tab open to a different site.

What SOP does not restrict SOP restricts reading cross-origin data. It does not, by itself, stop your page from loading a script, image, or stylesheet from another origin, and it does not stop an inline <script> from running just because an attacker injected it into your HTML. That gap — "same-origin doesn't mean same-trust" — is exactly the gap CSP was invented to close. You'll watch this gap get exploited, live, in Module 1 and closed in Module 3.
