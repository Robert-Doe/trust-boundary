Three nouns get used constantly and precisely throughout Track 1. Get them straight now — the modules will not redefine them.

Policy vs. Directive

Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.example.com; img-src *
└──────────────┬───────┘ └─────────┬────────┘ └──────────────────┬─────────────────┘ └────┬───┘
          header name          directive 1              directive 2                  directive 3
└─────────────────────────────────────value = the "policy"──────────────────────────────────────┘
  • A policy is the entire header value: one or more directives, separated by ;.
  • A directive is one name + source-list pair, e.g. script-src 'self' https://cdn.example.com.

Directive names fall into families: *-src directives (script-src, style-src, img-src, connect-src, …) control where resources of that type may load from; a few directives (frame-ancestors, form-action, base-uri, require-trusted-types-for) control structural behaviors that aren't about resource loading at all.

Source expression

Each directive's value is a space-separated list of source expressions — the individual things that are allowed. A source expression is one of:

FormExampleMatches
Hosthttps://cdn.example.comthat exact origin
Schemehttps:anything loaded over HTTPS, any host
Wildcard host*.example.comany subdomain of example.com
Keyword'self'the page's own origin — see below
Nonce'nonce-r4nd0m'an inline element carrying a matching nonce="r4nd0m" attribute
Hash'sha256-abc...'an inline element whose exact byte content hashes to that value

The keyword sources you'll see constantly

KeywordMeaning
'self'same origin as the document (scheme+host+port, exactly)
'none'nothing is allowed for this directive, full stop
'unsafe-inline'allow inline <script>/<style> and inline event handlers — named "unsafe" because it defeats most of CSP's XSS protection
'unsafe-eval'allow eval, new Function(), and string-form setTimeout

Fallback: how default-src works

default-src is not a "master switch" — it's a fallback value. If a specific *-src directive (like script-src) is absent from the policy, the browser uses default-src's value for it instead. The moment you write an explicit script-src, it fully replaces default-src for scripts — the two are never merged together.

Common misreading default-src 'self'; script-src https://cdn.example.com does not mean "scripts can come from 'self' OR the CDN." The explicit script-src completely overrides the fallback for scripts — only the CDN is allowed, not 'self'.
