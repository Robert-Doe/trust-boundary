What a "prototype" actually is

Every JS object has one hidden internal link to another object, called its prototype. When you read a property that isn't found directly on the object, the engine doesn't give up — it looks at the object's prototype, then that object's prototype, and so on, until it finds the property or runs out of links. 

function Animal(name) { this.name = name; }
Animal.prototype.speak = function () { return this.name + ' makes a noise'; };

const dog = new Animal('Rex');

dog.name;    // 'Rex'  — found directly ON dog
dog.speak(); // 'Rex makes a noise' — NOT on dog; found on Animal.prototype

Verified in Node:

node -e "..." → actual stdout
dog.__proto__ === Animal.prototype: true
dog instanceof Animal: true
speak found via chain: Rex makes a noise

The chain, drawn out

Verified: Object.getPrototypeOf(Animal.prototype) === Object.prototype → true. Object.getPrototypeOf(Object.prototype) → null, which is where every chain terminates.

instanceof is a chain walk, nothing more

a instanceof B walks a's prototype chain asking, at each link, "is this exact object === B.prototype?" It returns true the moment it finds a match, false if it reaches null first. That's the entire algorithm — no type name, no string tag, no declared "class" is consulted.

This has a sharp consequence, verified in Node:

node -e "..." → actual stdout
const fake = { name: 'Rex', speak: function(){ return 'fake' } };
fake instanceof Animal: false

const forged = Object.create(Animal.prototype);
forged instanceof Animal: true

fake has the exact same shape as a real Animal — same property names, a working speak method — and still fails instanceof, because its prototype link doesn't point at Animal.prototype. Meanwhile forged, an object with no real construction history at all, passes instanceof Animal, because Object.create(Animal.prototype) sets exactly the one link the check cares about. instanceof verifies a link, not an origin story.

Why this matters later If a browser API decided whether to trust a value using only instanceof TrustedHTML, the second example above shows the hole: any script that can reach TrustedHTML.prototype could forge a "trusted" value with Object.create. Real Trusted Types objects are not actually distinguished by a reachable prototype check alone — Module 22 shows you the real mechanism, and Module 23 shows exactly which forgery attempts it defeats and why.
