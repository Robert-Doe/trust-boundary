01 — The Big Analogy

form-action is a mail room that checks the destination address on every outgoing envelope before it leaves the building — no matter what someone wrote on the envelope's contents, if the address isn't on the approved list, it never gets mailed. base-uri is a completely different, subtler attack: imagine every unaddressed envelope in the building defaults to a "return address" stamp defined once, at the front desk. If someone sneaks in and swaps that front-desk stamp, EVERY unaddressed envelope in the building — ones that were never individually tampered with — now silently goes to the wrong place. base-uri protects the stamp itself, not any individual envelope.

02 — What Happens, Step by Step

  1. form-action: a page auto-submits a real <form> pointing at a different origin. Without CSP, the browser navigates there, carrying the form's data.
  2. With form-action 'self', the browser checks the form's target against the policy the moment submission is attempted — blocks it, fires a violation, and the page never navigates.
  3. base-uri: a page's HTML includes an (attacker-simulated) <base href="..."> tag pointing at a different origin, followed by a relative <img src="pixel.png">.
  4. Without CSP, the browser honors the injected <base> tag — the relative image request actually goes to the attacker's origin.
  5. With base-uri 'self', the browser refuses to apply the injected <base> tag at all — document.baseURI falls back to the document's own real URL, and the relative image resolves against the real origin instead.

05 — Limits / What You Cannot Do Yet

✗ CAN'T DO YET

  • Stop a form from submitting to an ABSOLUTE URL written directly by a legitimate developer — `form-action` restricts the target, not who wrote the form
  • Prevent the `<base>` tag injection itself — that's an HTML-injection bug, a separate problem from what happens once it exists
  • Recover a form submission or navigation that already happened before the policy could apply

✓ CAN DO

  • Stop any form on the page — including ones injected by an attacker — from submitting to an untrusted origin
  • Neutralize an entire class of attack (base-tag hijacking) that would otherwise silently redirect every relative URL on the page, with zero changes to any individual link
  • Verify both defenses via the actual real-world consequence (a real navigation, a real network request), not just a console message

07 — Brain Exercise

Think it through before revealing

A page has NO injection vulnerability anywhere — every `<base>` tag, every form, every link is entirely under the developer's own control, written by hand, never touched by user input. Does `base-uri`/`form-action` still provide any real value on that page?

Reveal the answer:

Yes, though the value shifts from "stops an active attack" to "reduces blast radius if something else goes wrong later." Software changes over time — a future contributor might add a feature that echoes user input somewhere nobody expected, a dependency might introduce its own injection bug, a build tool might mistakenly inline untrusted content. `base-uri` and `form-action` don't assume the rest of the page is perfect; they assume it might not stay that way, and cap the damage a NEW, not-yet-discovered bug could do. This is the same defense-in-depth argument from Module 11's Brain Exercise, applied to two more attack shapes: CSP earns its keep most when something else has already gone wrong.

08 — There Are No Dumb Questions

Q: Why did `document.baseURI` fall back to the page's FULL URL (including path), not just its origin?

Because that's what `document.baseURI` resolves to when there's no effective `<base>` element at all — the document's own address IS the default base for resolving every relative URL on it, path included. `base-uri 'self'` didn't substitute some other default; it simply prevented the injected tag from overriding what was already the correct, ordinary default.

Q: Could `form-action` have a value like `'self' https://payment-processor.example` for a real checkout flow?

Yes — exactly the intended real-world shape. Most sites need forms to submit to at least one trusted third party (a payment processor, an OAuth provider). `form-action` supports the same source-expression list syntax as every other directive; `'none'` and `'self'`-only are just the strictest possible choices, appropriate for this module's demonstration.

Q: Does `base-uri` affect absolute URLs anywhere on the page?

No — an absolute URL (`https://example.com/thing`) never consults the base at all; only genuinely relative references (`thing`, `./thing`, `../thing`) do. This is exactly why the attack is dangerous: it doesn't touch any URL directly, it only changes what "relative" resolves against, silently, for every relative reference on the page at once.
