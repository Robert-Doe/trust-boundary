Vocabulary Web · "Policy" OverloadingConcept: Directive (CSP)

A directive is ONE named rule inside a policy — one line item in the rulebook, not the rulebook itself. script-src 'self' is a directive. require-trusted-types-for 'script' is a directive. A policy is nothing but a list of these, joined by semicolons.

What it looks like

script-src 'self' 'nonce-abc123'
└───┬────┘ └────────┬────────┘
  name         source list (the directive's VALUE)

Where you've seen it

  • Modules 3, 5, 6, 7 — script-src, governing script execution
  • Module 12 — frame-ancestors, a structural directive with no source list in the usual sense
  • Module 15 — require-trusted-types-for, the directive that turns on Trusted Types enforcement
  • Module 20 — trusted-types, a DIFFERENT directive (confusingly similar name!) that allowlists policy NAMES
The sharpest confusion this term causes require-trusted-types-for and trusted-types are TWO DIFFERENT CSP directives with almost-identical names and completely different jobs — one turns on enforcement, the other restricts policy names. See the sibling vocabulary web in Module 20's folder for that specific pair, disambiguated in full.
How this connects to the other terms A directive lives inside a CSP policy. It is NOT the same thing as a Trusted Types rule (the createHTML/createScript functions) — different layer entirely, even though both could loosely be called "a rule." See the connection hub.
