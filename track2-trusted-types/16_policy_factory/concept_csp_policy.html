Vocabulary Web · "Policy" OverloadingConcept: CSP Policy

A CSP policy is the full text of one Content-Security-Policy header's value — the entire rulebook for one page, cover to cover. It's not one rule; it's the whole document that contains all of them.

What it looks like

Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-abc123'; frame-ancestors 'none'
                          └──────────────────────────── the POLICY ────────────────────────────┘

Where you've seen it

  • Every Track 1 module — the entire header value passed to res.writeHead
  • Module 8 — proved TWO of these can be active on one page at once, combined by intersection
  • Module 2 — the parser this course built takes a policy STRING and turns it into a directive→source-list object

What it's built from

A policy is made of one or more directives (see that term's own page) separated by semicolons. It has no rules of its own directly — every actual restriction lives inside a directive.

How this connects to the other terms A CSP policy contains directives. It shares its name — and nothing else — with a completely different concept, Trusted Types policy, introduced starting Module 16. See the connection hub for the full picture and a table of exactly how people mix these two up.
