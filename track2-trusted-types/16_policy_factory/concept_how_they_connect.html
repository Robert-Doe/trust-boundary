Vocabulary Web · HubHow "Policy," "Directive," "Trusted Types Policy," and "Rule" Connect

Four terms, two of which share a single English word ("policy") despite naming completely different things at completely different layers. This page exists because that overlap is exactly the kind of thing that causes real confusion under time pressure — the same way "booting/bootstrapping/ BIOS/bootloader" get conflated in OS contexts.

Commonly Confused Pairs

Wrong statementWhy it's wrong / the correction
"The `trusted-types` CSP directive controls what a Trusted Types policy's rules are allowed to do." No — verified in Module 20, it only controls WHICH NAMES can be used to create a policy at all. It has zero opinion about what a rule function does once the policy exists (Module 17's Brain Exercise: a totally permissive rule is still a "valid" policy).
"A CSP policy and a Trusted Types policy are the same kind of thing, just for different purposes." No — one is a string sent over HTTP and parsed/enforced by the browser before page script runs; the other is a JS object your own running code creates. Different layers, different lifetimes, different mechanisms entirely.
"A directive and a rule are basically the same idea — both are 'a rule.'" Only in casual English. A directive is declarative data in an HTTP header (no code runs). A rule is an actual function that executes and can do arbitrary computation (Module 16's uppercase transform, Module 24's real sanitization).
"require-trusted-types-for and trusted-types are the same directive, just written two ways." No — two entirely separate CSP directives with confusingly similar names. `require-trusted-types-for 'script'` (Module 15) turns ON enforcement. `trusted-types <names>` (Module 20) restricts WHICH policy names may be created. See Module 20's own vocabulary web for this specific pair.

Scenario-Matching Quiz

1. A server sends `Content-Security-Policy: require-trusted-types-for 'script'; trusted-types approved-name`. Which TWO of the four terms on this page appear in that single header value?
Reveal answerPolicy (the whole string) and Directive (each of the two semicolon-separated parts) — no Trusted Types policy object or rule exists yet; nothing in JS has run.
2. `trustedTypes.createPolicy('approved-name', { createHTML: (s) => s.trim() })` runs successfully. Which term does `(s) => s.trim()` correspond to?
Reveal answerA Rule — specifically the `createHTML` rule. The object `createPolicy` returns is the Trusted Types Policy; the function passed in as one of its properties is the Rule.
3. A teammate says "I added a new CSP directive to loosen our Trusted Types rules." What's imprecise about that sentence?
Reveal answerCSP directives (HTTP-layer) can't touch a rule's logic (JS-layer) at all — they can only affect WHETHER Trusted Types is enforced at all (`require-trusted-types-for`) or WHICH policy names may exist (`trusted-types`). "Loosening a rule" would mean editing the actual `createHTML`/`createScript` function in JS source — a code change, not a header change.
