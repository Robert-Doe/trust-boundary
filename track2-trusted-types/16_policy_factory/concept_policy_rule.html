Vocabulary Web · "Policy" OverloadingConcept: Rule (Trusted Types)

A rule is the plain JS function YOU write and hand to createPolicy — createHTML, createScript, or createScriptURL. It's the one piece of this whole vocabulary web that's ordinary, unprivileged JavaScript: no special syntax, no browser magic, just a function that takes a string and returns a string.

What it looks like

trustedTypes.createPolicy('my-policy', {
  createHTML: (input) => input.toUpperCase(),  // ← THIS is a rule
});

Where you've seen it

  • Module 16 — a trivial rule (uppercase), proven to really execute via a counter
  • Module 17 — the "default" policy's rule, auto-invoked for legacy code
  • Module 24 — a real rule: (input) => DOMPurify.sanitize(input)

What a rule is NOT

A rule is not itself checked for safety by the platform in any way — Module 17's Brain Exercise made this explicit: a rule that just echoes its input unchanged is a completely valid, "working" rule that provides zero actual protection. The platform only guarantees a value passed THROUGH some rule; it has no opinion on whether that rule does anything useful.

How this connects to the other terms A rule is the one piece OF a Trusted Types policy that you author yourself. It has no CSP equivalent at all — nothing in a CSP directive or policy lets you supply custom transformation logic; CSP only ever allows or blocks, it never transforms.
