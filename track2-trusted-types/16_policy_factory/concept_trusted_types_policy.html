Vocabulary Web · "Policy" OverloadingConcept: Trusted Types Policy

A Trusted Types policy is a JS OBJECT — the return value of trustedTypes.createPolicy(name, rules) — not a string, not an HTTP header, and not part of the CSP header value at all. It's callable code with a name attached, living in your page's running JavaScript, that produces branded values when you call its methods.

What it looks like

const policy = trustedTypes.createPolicy('my-policy', {
  createHTML: (input) => sanitize(input),
});
typeof policy;              // "object"
typeof policy.createHTML;   // "function"

Where you've seen it

  • Module 16 — introduced; proved it returns an object exposing all three creator methods
  • Module 17 — the special name "default", auto-invoked for legacy code
  • Module 20 — WHICH names are allowed to become a Trusted Types policy at all
  • Module 24 — a real policy wrapping DOMPurify
The confusion this term causes It shares the single word "policy" with the CSP policy concept (the whole header value) — but a Trusted Types policy is a runtime JS object your code creates and calls methods on; a CSP policy is a string the SERVER sends as a header, parsed and enforced by the browser before your page's own script ever runs. They exist at completely different layers.
How this connects to the other terms A Trusted Types policy is created BY a CSP directive permitting it to exist (require-trusted-types-for + trusted-types), but is itself a completely separate JS-level object, not a CSP construct. It's built from rules (see that term). See the connection hub.
