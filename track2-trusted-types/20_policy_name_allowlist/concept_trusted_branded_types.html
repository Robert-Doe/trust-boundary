Vocabulary Web · The Trusted Types Directive FamilyConcept: TrustedHTML / TrustedScript / TrustedScriptURL

These are the STAMPED, APPROVED DOCUMENTS — the actual VALUES a policy's create* methods return, and the ONLY values a guarded sink will accept. Three distinct types for three distinct sink families: HTML sinks want TrustedHTML; eval/Function/ script.text want TrustedScript; script.src wants TrustedScriptURL.

What they look like

policy.createHTML('...')       // → a TrustedHTML value
policy.createScript('...')     // → a TrustedScript value
policy.createScriptURL('...')  // → a TrustedScriptURL value

trustedHTMLValue instanceof TrustedHTML;  // true for a REAL one

Where you've seen them

  • Module 16 — proved `createHTML`'s output is `instanceof TrustedHTML`, `typeof 'object'`, NOT `instanceof String`
  • Module 18 — proved the HTML sink family accepts a real `TrustedHTML` uniformly, rejects imitations
  • Module 19 — proved `TrustedScript`/`TrustedScriptURL` gate `eval` and `script.src` (with real gaps found in `Function()` and `.text`)
  • Module 22 — proved `instanceof TrustedHTML` can be spoofed, but the real sink guard can't
Don't confuse the type with the sink it guards TrustedHTML is a VALUE TYPE. innerHTML is a SINK that demands values of that type. They're not the same word for the same thing — a sink "requires TrustedHTML," it isn't itself called TrustedHTML.
How this connects to the other terms These three types are what a Trusted Types policy's methods produce. Whether producing them is even possible at all depends on the two CSP directives: require-trusted-types-for (must be present for sinks to demand these types) and trusted-types (must allowlist the policy name that produces them).
